> **In one sentence.** A model is a very large table of numbers, and everything in this field is a way of making that table, shrinking it, moving it, or reading it fast.

You keep models because you intend to do something with them. This course
is the something: the working knowledge behind every file in a bundle and
every verb on a workbench, from the cluster that trained the weights to the
laptop that runs them tonight. Fourteen pages, in an order that builds. Each
one ends where the next begins, carries the arithmetic you will actually
use, and points at the darsay command that lets you try it on your own vault.

<Journey />

## What a workbench is

A **vault** is where bytes are kept, pinned and hashed, and never edited.
A **workbench** is where bytes are worked on: a machine with the runtimes,
the converters, and the training tools installed, where a hydrated bundle
becomes a quantized copy, a fine-tuned variant, or a served endpoint. The
vault answers *what exactly do we have*; the workbench answers *what can we
make of it*. Keeping them apart is what lets you experiment freely without
ever wondering whether the original is still the original.

The pages under **Made** and **Worked** are about the bench. The pages
under **Kept** are the rest of this site. If you only ever want to run a
model, read the first three pages and *Running it locally*; if you want to
change one, read to the end.

## How to use the board while you learn

Every board row carries a **field guide**: press `?` on a board, or click any
chip, fact, or lens. The guide's cards are the short form of these pages,
and when you open one from a row it applies the lesson to that row's own
numbers: this model's weights at this precision, the memory it would need,
the compute that made it. Read a page here, then go find a row that shows
it. The two are written to be read together.

<div class="docs-note"><strong>The arithmetic you will use most.</strong> Weights take parameters × bytes per parameter. A dense model reads all of its weights once per token, so a single stream's speed is memory bandwidth ÷ weight bytes. The KV cache costs 2 × layers × KV heads × head dimension × bytes for every token of context. Training costs about 6 × parameters × tokens in floating-point operations, and holding the optimizer states costs 16 bytes per parameter. Every page below is an elaboration of one of those four lines.</div>
