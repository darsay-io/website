# darsay.io website

Astro + Starlight + a Cloudflare Worker for anonymous want-list boards.

- Docs Markdown is generated (`npm run sync-docs`) from the CLI GitHub Release pinned in `docs.lock.json`. Do not hand-edit `src/content/docs/docs/**`. Bump the lock with `npm run bump-docs-lock` (or the `Sync CLI docs` workflow), never by editing the JSON alone. A CLI release normally needs no hands at all: release → `Sync CLI docs` (commits the pin to `main`) → `Deploy` (RUNBOOK § Docs lock). The **site-authored** docs — the board, for agents — live in `src/content/docs/board/*.mdx` with an explicit `slug: docs/board/…` and are never touched by the sync; `primer.test.ts` resolves `/docs/board/…` links against them by that slug. They use `src/components/docs/Route.astro` (method · path · scope) and `Stage.astro` (the board's terminal chrome); styles are the `.api-*`/`.docs-*` block at the end of `site.css`.
- The site never stores model bytes. JSON API only. No R2.
- Board URL is the capability. No accounts. No Turnstile in v1. **Keys** (`src/worker/access.ts`, table `keys`) are that capability narrowed: one board, scopes `read`/`write`/`claim`/`remove` (read implied), a label; the secret is `darsay_` + 48 hex, stored as a SHA-256. A key addresses the board at `/api/board/…` (the bearer names the board; the document it reads has no `id`/page link) and at `/mcp`; on `/api/boards/:id/…` a bearer is honored for attribution and narrowing, never widening. The board id itself is accepted as a bearer. Keys can never delete the board, mint keys, or touch webhooks (`url_required`); a key without `remove` cannot destroy a row — the catalog import *drops* rows it would have pruned.
- **One write path.** Every mutation — page, CLI round trip, key, MCP — is an operation in `src/worker/ops.ts` that ends in `ledger.commit`: one D1 batch that spends a mutate, bumps `boards.revision`, stamps `entries.updated`, appends `audit` rows (actor, action, entry, before/after of the decided columns, revision) and prunes past 1000, then `announce`s to `webhooks` via `waitUntil`. `index.ts` is routing only: one Hono sub-app mounted at both `/boards/:id` and `/board`, a gate (id check, lookup cap, grant, board load), and an `Idempotency-Key` middleware (fingerprint = method+path+body; replay with `Idempotent-Replayed: true`; mismatch 422). `GET` sends `ETag: "<revision>"`; writes honor `If-Match` (412 `stale`). `/b/<id>.json` and `Accept: application/json` on `/b/<id>` rewrite to the API in the worker's `fetch`; `/openapi.json` and `/mcp` are root aliases, so both are in `run_worker_first`.
- **Rows, not cards.** The API keeps the board's words: rows with `status` want/have and `desire` (the order is desire desc, unrated last, then id), no columns, no positions, no free-text tags — `address` (kind/provider/locator/url) and `lineage` (from `src/lib/lineage.ts`) are read from the work. A row's identity is its address (source + revision + include); `POST /entries` is an upsert on it. **Drop** (`entries.dropped` timestamp) is the soft removal: dropped rows leave every default list, the catalog export, and claims (409 `dropped`); a re-add or an import that names the address restores them; `?dropped=all|only` shows them; the page's Drop button drops (toast Undo) and the ✦ Agents panel restores. **Remove** (`DELETE`) is permanent and needs `remove`.
- `apply` (declarative: match by address, add/update/restore/unchanged, `mode: sync` drops the rest) and `batch` (explicit ops by address or id) share the pure planner in `src/worker/apply.ts`; both are all-or-nothing with `failures[]`, take `dry_run`, cap at 100 rows, and price at most `PRICE_BUDGET` (12) new Hub rows per call (subrequest budget on the free plan) — the rest land unpriced for the CLI's round trip.
- `src/worker/openapi.ts` builds the OpenAPI 3.1 document from one route table; `openapi.test.ts` holds it against `app.routes` both ways (URL-only ops answer 403 on the key address and are deliberately undescribed there). `src/worker/mcp.ts` is a stateless Streamable-HTTP MCP server with no SDK: JSON-RPC over POST, `initialize`/`ping`/`tools/list`/`tools/call`, twelve tools over the same ops plus `explain` (the field guide, also public at `GET /api/guide[/:chip]` via `src/worker/guide.ts`). Tests run on real SQLite (`node:sqlite`, `src/worker/testdb.ts`) with the repository's migrations, so every new table is exercised by the SQL production runs.
- `CREATE_PASSWORD` is a Wrangler secret for POST `/api/boards` only. Never put it in git, `wrangler.jsonc` vars, or client JS.
- The vocabulary is the CLI's (`docs/NORTH-STAR.md` in the CLI repo): **negative** and **print** (never *master*), **precision** and bytes per parameter, **family / generation / member** read from a work's name, and **closed** works. Chips, lenses, cards, and copy use those words and no others.
- `catalog.json` export is schema 2.0.0 and still carries no holders/status/claims/GUID. POST of the same path imports a catalog document (the darsay CLI round trip): authoritative for entries/desire/note/digests, upsert+prune by (source, revision, include set); board-side fields survive on kept rows. Only the current major imports — fix forward, no migration.
- A row's `source` may be a **home URL** (`https://` on a non-Hub host, with a path): a **closed** work — an API-only model, an announced release. `canonicalizeSource` returns `kind: "home"`; the worker stores it verbatim (minus fragment), prices nothing, refuses a revision or include on it, and `entryToApi` sets `closed: true`. The board renders it dashed with a `closed` chip, no size, no Have/Who, and it sits in its family by the name at the end of the URL.
- The digest carries `precision`, `bytes_per_param`, `architecture`, and `parents` (schema 2.0.0). `src/worker/precision.ts` is a port of the CLI's `precision.py` (labels from `config.json` — `quantization_config` wherever nested — the dominant dtype, or GGUF file names; measured bytes per parameter); the worker fetches `config.json` on add when the repo has one under 1 MiB, and reads `base_model` card fields and `base_model:<relation>:` tags into `parents`. The CLI's refresh overwrites all of it. Change the CLI first, then mirror here.
- `src/lib/lineage.ts` is a port of the CLI's `lineage.py`: family, generation, member, variants, formats, size — read from the name and labeled so. `src/lib/lineage-fixtures.json` is a copy of the CLI's `tests/fixtures/lineage-names.json`; both suites run the same table, so a grammar change lands in both repos with the same fixture. Family lens chips, `--sort family`'s order (`compareFamily`), and the **Lineage** view (`renderLineage` in `board.ts`: families → generations oldest first → members smallest first, a derivative nested under the parent its digest declares when that parent is on the board) all read from it. View and family live in the URL fragment (`#view=lineage&family=qwen`).
- Claims (`claim_json`, `POST/DELETE /api/boards/:id/entries/:eid/claim`) are board-side coordination like holders/status — never exported in catalog.json. Reporting `done` is the one client write to human columns (status→have; empty holders learns the client). A row with status `have` refuses un-marked claims (409 `{"error":"have"}`) — `refetch: true` (the CLI's `archive SOURCE --board`), `force`, or the holder's own continuing reports go through; that is what stops an out-of-date `--next` from re-downloading what the group holds. `entryToApi` filters claims past `CLAIM_TTL_MS` (`liveClaim`), so an abandoned claim stops rendering as in flight the moment it stops blocking new ones.
- Tests: `npm test`. Build: `PUBLIC_BOARDS_ENABLED=true npm run build`.
- Do not put a Node toolchain in `darsay/darsay` (the Python CLI repo).
- Provisioning is Wrangler + `ops/RUNBOOK.md`. Do not add Terraform, Ansible, or D1 auto-provision (omit `database_id`).
- `public/robots.txt` may only Disallow `/b/`, `/api/`, `/boards`. Do not add GPTBot/ClaudeBot (or other AI crawler) Disallows; product docs should stay fetchable. Cloudflare dashboard AI-bot policy lives in `ops/RUNBOOK.md`.
- Board lenses (filters) live in `src/lib/lenses.ts` and the field guide (teaching cards) in `src/lib/primer.ts` + `src/lib/guide.ts`. Lenses are pure and decided from entry fields; hint lenses read the CLI's closed vocabulary (`gated`/`large`/`quant`/`redundant`/`subset`), the `negatives` lens reads the digest's `policy`, `closed` reads the address, and name lenses (`abliterated`, `base`, `moe`, `spec`) read the repo name and say so in their blurb. Field-guide `doc` anchors must resolve against the docs currently synced under `src/content/docs` (the pinned CLI release), so a card that teaches something the pinned docs do not yet have a heading for links to the page, not an anchor, until the next docs sync. Lens/sort state lives in the URL fragment only (`#lens=…&sort=…`), never sent to the server. Primer copy is authored text rendered through `inline()` (backticks/`**`/`*`); every `doc` anchor is checked against `src/content/docs` by `primer.test.ts`, so a docs re-sync that renames a heading fails the suite on purpose. Sizes in cards and row notes are GiB (the board's and the CLI's unit); recipe `#` comments keep the cookbook's wording. `src/lib/rownote.ts` is the card applied to the row it was opened from — pure text from entry fields, tested. Claims semantics (report at start / clean pause / registration, 24 h expiry) and `--next` order (partial, then desire, unrated last) come from `catalogs.mdx` and the CLI's `next_entry`; keep the desire and claims cards true to them.
- `src/worker/hints.ts` is a port of the CLI's `hints_for`/`derive_hints`/`_dominant_format` (same 20 GiB line, 1.75× redundancy factor, dtype widths). The worker writes `hints` into the digest on add and derives them for older digests in `entryToApi`; the CLI's refresh overwrites both. Change the CLI first, then mirror here.
- Board recipe cards live in `src/lib/recipes.ts`: static, derived from entry fields plus the board page's own URL (no new catalog fields, no fetch per card). The `board` recipe teaches `archive SOURCE --board <board-url>` with the row's exact identity (source + revision + include) so the CLI's claim matches the row; the flag ships in CLI releases after 0.14.8. Command wording mirrors the CLI's `examples/README.md`; user text only ever appears inside `shellQuote`/`quoteGlob` single quotes, never in `#` comments, and is rendered with `textContent`.
