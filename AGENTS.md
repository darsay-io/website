# darsay.io website

Astro + Starlight + a Cloudflare Worker for anonymous want-list boards.

- Docs Markdown is generated (`npm run sync-docs`) from the CLI release or exact commit pinned in `docs.lock.json`. Do not hand-edit `src/content/docs/docs/**`. Bump the lock with `npm run bump-docs-lock -- <vX.Y.Z-or-full-commit-sha>` (or the `Sync CLI docs` workflow), never by editing the JSON alone; this regenerates pages and snapshots together. An exact commit pin stays fixed until an explicit release tag is supplied. Publish the CLI commit before pushing a website commit that pins it. A CLI release normally needs no hands at all: release → `Sync CLI docs` (commits the pin to `main`) → `Deploy` (RUNBOOK § Docs lock). **The page list is derived, never typed:** every `docs/*.md` in the pinned source publishes as `/docs/<stem>/` (`README.md` is `/docs/`), plus `examples/README.md` at `/docs/examples/` — a new CLI docs page needs no edit here, because there is no map to forget. **Links stay strict.** A relative link resolves against the file that wrote it and must name something the source checkout has: a published page becomes its slug, a copied asset (`ASSETS` in `sync-docs.mjs`) its site path, anything else in the repo a GitHub blob at the pinned SHA; a target the source lacks fails the sync, because a dead link on darsay.io is worse than a red run. The sidebar is computed the same way — `scripts/sidebar.mjs` holds placement and wording for the pages we know, and any synced page nobody placed lands at the end of *Using the vault* under its own title; `sidebar.test.mjs` holds both directions (every page appears exactly once, no entry without a page). The transform also takes the body's H1 off the top (Starlight prints the frontmatter `title`, so it would print twice), writes a `description` that is whole sentences (the `**In one sentence.**` blockquote, the README's tagline, or the first prose paragraph — never the first line of one), and an `editUrl` to the source file on the CLI's `main`.
- The transform runs in the **CLI's** CI too (`Docs site transform`, on every PR and as a `needs:` of its release), so a new page or a renamed heading fails there — before the tag — rather than in `Sync CLI docs` after it. When a sync does fail anyway it opens one `docs-sync` issue for the tag and skips that tag while `main` is unchanged, instead of re-running the identical input hourly; push the fix to `main` and the next cron run retries on its own (RUNBOOK § Docs lock, *When a sync fails*).
- The **site-authored** docs live in two directories the sync never touches, each page with an explicit `slug:` line: the board, for agents, in `src/content/docs/board/*.mdx` (`slug: docs/board/…`), and **Learn the field** — the course on training, precision, quantization, the transformer, local inference, and the workbench — in `src/content/docs/learn/*.mdx` (`slug: docs/learn/…`). `AUTHORED_DIRS` in `scripts/sidebar.mjs` lists both; `primer.test.ts`, `llms.mjs`, and `sidebar.mjs` resolve slugs against every directory in it, so a third directory is one line there. The board pages use `src/components/docs/Route.astro` (method · path · scope) and `Stage.astro` (the board's terminal chrome); the Learn pages add `MemoryLab.astro` and `TrainingLab.astro` (calculators, vanilla `<script>`, every number a rule of thumb the page states), `Loop.astro` (the training loop as SVG), `Ruler.astro` (bytes per parameter to scale), and `Journey.astro`. Styles are the `.api-*`/`.docs-*`/`.journey-*`/`.ruler-*`/`.loop*`/`.lab-*` blocks at the end of `site.css`. Learn pages open with an `**In one sentence.**` blockquote (the docs lede), teach with the four lines of arithmetic the map page names (weights, bandwidth, KV cache, 6ND and 16 bytes), quote only CLI verbs that exist, and end with *Where this bites*. The field guide's **The workbench** group (`training`, `posttrain`, `finetune`, `memory`, `runtime`, `convert`, `workbench` in `primer.ts`) is the short form of those pages, each with a row note in `rownote.ts` computed from the row's own parameters, bytes per parameter, name, and classification.
- **The docs' reading surface is `src/styles/docs.css`** (unlayered, so it wins over Starlight's `@layer starlight.*` on sight): serif italic `h2` with a ✦, a lede from the page's first paragraph or its `**In one sentence.**` blockquote (the label becomes the eyebrow), kicker table heads, the sidebar and *On this page* as gold kickers. Code blocks are Expressive Code with the site's own theme (`scripts/code-theme.mjs`, a VS Code theme in shape) and the board's terminal chrome in `styleOverrides` (astro.config.mjs); the three dots are recoloured in `docs.css`. **One palette:** the site is dark only — `ThemeProvider.astro` in `src/components/starlight/` pins `data-theme="dark"` and `ThemeSelect.astro` renders nothing. There is no light palette; do not add the picker back without one.
- The site never stores model bytes. JSON API only. No R2.
- Board URL is the capability. No accounts. No Turnstile in v1. **Keys** (`src/worker/access.ts`, table `keys`) are that capability narrowed: one board, scopes `read`/`write`/`claim`/`remove` (read implied), a label; the secret is `darsay_` + 48 hex, stored as a SHA-256. A key addresses the board at `/api/board/…` (the bearer names the board; the document it reads has no `id`/page link) and at `/mcp`; on `/api/boards/:id/…` a bearer is honored for attribution and narrowing, never widening. The board id itself is accepted as a bearer. Keys can never delete the board, mint keys, or touch webhooks (`url_required`); a key without `remove` cannot destroy a row — the catalog import *drops* rows it would have pruned.
- **One write path.** Every mutation — page, CLI round trip, key, MCP — is an operation in `src/worker/ops.ts` that ends in `ledger.commit`: one D1 batch that spends a mutate, bumps `boards.revision`, stamps `entries.updated`, appends `audit` rows (actor, action, entry, before/after of the decided columns, revision) and prunes past 1000, then `announce`s to `webhooks` via `waitUntil`. `index.ts` is routing only: one Hono sub-app mounted at both `/boards/:id` and `/board`, a gate (id check, lookup cap, grant, board load), and an `Idempotency-Key` middleware (fingerprint = method+path+body; replay with `Idempotent-Replayed: true`; mismatch 422). `GET` sends `ETag: "<revision>"`; writes honor `If-Match` (412 `stale`). `/b/<id>.json` and `Accept: application/json` on `/b/<id>` rewrite to the API in the worker's `fetch`; `/openapi.json`, `/mcp`, `/mcp/server-card`, and `/.well-known/mcp-server-card` are root aliases, so all four are in `run_worker_first`. The API's after-middleware applies its defaults only where the handler set nothing, so a public document's own `Cache-Control` stands (`/openapi.json` ten minutes, the card an hour; everything else `no-store`). `/b/<id>` is one static shell for every board, so the worker writes `<link rel="alternate" type="application/json" href="/b/<id>.json">` and a `Link` header into it for a valid id — no lookup, nothing about the board is read.
- **Rows, not cards.** The API keeps the board's words: rows with `status` want/have and `desire` (the order is desire desc, unrated last, then id), no columns, no positions, no free-text tags — `address` (kind/provider/locator/url) and `lineage` (from `src/lib/lineage.ts`) are read from the work. A row's identity is its address (source + revision + include); `POST /entries` is an upsert on it. **Drop** (`entries.dropped` timestamp) is the soft removal: dropped rows leave every default list, the catalog export, and claims (409 `dropped`); a re-add or an import that names the address restores them; `?dropped=all|only` shows them; the page's Drop button drops (toast Undo) and the toolbar's "N dropped" opens the dropped rows dialog (`src/lib/dropped.ts`) to restore. **Remove** (`DELETE`) is permanent and needs `remove`.
- `apply` (declarative: match by address, add/update/restore/unchanged, `mode: sync` drops the rest) and `batch` (explicit ops by address or id) share the pure planner in `src/worker/apply.ts`; both are all-or-nothing with `failures[]`, take `dry_run`, cap at 100 rows, and price at most `PRICE_BUDGET` (12) new Hub rows per call (subrequest budget on the free plan) — the rest land unpriced for the CLI's round trip.
- `src/worker/openapi.ts` builds the OpenAPI 3.1 document from one route table; `openapi.test.ts` holds it against `app.routes` both ways (URL-only ops answer 403 on the key address and are deliberately undescribed there). `src/worker/mcp.ts` is a stateless Streamable-HTTP MCP server with no SDK, JSON-RPC over POST, serving **two eras** of the protocol on one endpoint: a request that names its version in `params._meta` is revision 2026-07-28 (no handshake; `server/discover`, `tools/list`, `tools/call`; `MCP-Protocol-Version`/`Mcp-Method`/`Mcp-Name` headers must agree with the body or the answer is 400 `-32020`; an unspoken version is 400 `-32022` with `supported`; an unknown method 404 `-32601`; every result carries `resultType` and `serverInfo` in `_meta`, `tools/list` a `ttlMs`), and a request without one is the `initialize` era (2025-11-25 and earlier: `initialize`/`ping`/`tools/list`/`tools/call`, always 200). `server/discover` is answered to any bearer with or without `_meta`. This is the one place the greenfield rule does not apply: the era is the *client's* protocol, not ours, and today's clients with reach still open with `initialize`. No `Origin` check — a public server with a bearer and no cookies. Twelve tools over the same ops plus `explain` (the field guide, also public at `GET /api/guide[/:chip]` via `src/worker/guide.ts`). `MCP_SERVER.version` is the card's `version`; bump it when the tools change, because the registry refuses a version it already has. Tests run on real SQLite (`node:sqlite`, `src/worker/testdb.ts`) with the repository's migrations, so every new table is exercised by the SQL production runs.
- **Discovery.** `src/worker/card.ts` is the server card — endpoint, revisions, the `Authorization` header — in the MCP Registry's `server.json` shape (the card proposal, SEP-2127, is a subset of it and still a draft; when its own schema goes live only `$schema` moves), served at `/.well-known/mcp-server-card` and `/mcp/server-card`, cacheable an hour, and the very file `mcp-publisher publish` reads (RUNBOOK § MCP discovery). Every HTML page carries `<link rel="mcp">` to it (Plain layout + Starlight `head`) and `public/_headers` a `Link` header; the board document names it in `links.card`. `/llms.txt` is an Astro endpoint over `scripts/llms.mjs`: the sidebar's own page list and groups, each page's frontmatter description cut at its last whole sentence — derived, never typed, like the sidebar; `llms.test.mjs` holds every page to exactly one line. Tools are listed nowhere but `tools/list`. No JSON-LD and no `darsay:*` meta on board pages: a board is not a schema.org Dataset, the pages are `noindex`, and the id is already in the URL. `/agents/` (`src/pages/agents.astro`) is the same discovery surface as a page — every interface an ordinary `<a href>` in static HTML, plus how a board's id names its operations — for a reader that sees neither `<head>` nor headers; every page's footer links to it (the Plain layout; the docs through the Starlight `Footer` override in `src/components/starlight/`), the board shell's body links to it beside a `data-board-json` marker the worker turns into a link to the board's own JSON, and `llms.txt` lists it under *Optional*. `src/lib/discovery.test.ts` holds the page to `machineInterfaces()` and to routes that exist (a test file under `src/pages` would become a route). Boards stay out of search and the walk never leads back to one: `robots.txt` disallows `/b/`, `_headers` and the worker send `X-Robots-Tag: noindex, nofollow`, the shell and the create page pass `noindex` to the Plain layout (a `robots` meta), the sitemap filters them, and `/agents/` and `llms.txt` never name a board.
- `CREATE_PASSWORD` is a Wrangler secret for POST `/api/boards` only. Never put it in git, `wrangler.jsonc` vars, or client JS.
- The vocabulary follows the CLI's `docs/NORTH-STAR.md`: collection **scope**, artifact **identity and lineage**, **recovery evidence**, and the **retain/omit decision** are separate concepts. **Negative** and **print** remain optional teaching shorthand, never an omission policy. **Precision** and bytes per parameter describe encoding; **family / generation / member** are read from a work's name; **closed** names a work without fetchable weights. Copy must state what evidence establishes each claim.
- `catalog.json` export is schema 3.0.0 and still carries no holders/status/claims/GUID. POST of the same path imports a catalog document (the darsay CLI round trip): authoritative for entries/desire/note/digests, upsert+prune by (source, revision, include set); board-side fields survive on kept rows. Only the current major imports — a catalog is not migrated (a bundle's *record* is, by the CLI's `darsay migrate`); re-add its rows to a new board.
- A row's `source` may be a **home URL** (`https://` on a non-Hub host, with a path): a **closed** work — an API-only model, an announced release. `canonicalizeSource` returns `kind: "home"`; the worker stores it verbatim (minus fragment), prices nothing, refuses a revision or include on it, and `entryToApi` sets `closed: true`. The board renders it dashed with a `closed` chip, no size, no Have/Who, and it sits in its family by the name at the end of the URL.
- The digest carries `precision`, `bytes_per_param`, `architecture`, and `parents` (schema 3.0.0). `src/worker/precision.ts` is a port of the CLI's `precision.py` (labels from `config.json` — `quantization_config` wherever nested — the dominant dtype, or GGUF file names; measured bytes per parameter); the worker fetches `config.json` on add when the repo has one under 1 MiB, and reads `base_model` card fields and `base_model:<relation>:` tags into `parents`. The CLI's refresh overwrites all of it. Change the CLI first, then mirror here.
- **Every size has a scope.** `size_basis` is `repository`, `selection`, or `archive`; `payload_bytes` measures that scope, and `repository_bytes` records the full inventory separately. `unknown_size_count` makes the amount a lower bound. CLI classification records `verdicts`, `skipped_bytes`, and `unclassified_count`; an archive includes retained prints, support files, and unresolved weight sets. An artifact's format or parent relationship is separate from recovery evidence and the omission decision. `parameters_source` names safetensors or GGUF metadata. `gguf_variants` always describes the repository's model GGUF inventory, including shard completeness and exact include selectors. `src/lib/size.ts` renders scope next to row and lineage amounts; totals group scope and status separately and do not claim deduplicated vault storage. `Refresh size` POSTs the row identity plus `refresh: true` to `/entries`, refreshing Hub inventory without changing decided columns. Archive classification uses the CLI.
- **Collection scope precedes retention.** Teaching cards distinguish collection scope, artifact lineage, recovery evidence, and the final retain/omit decision. Negative/print shorthand and encoding labels do not justify omission. Automatic skipping is limited to R15 byte duplication with a retained source in the same bundle; R2 upstream duplicates remain retained and R9 colocated GGUF remains unknown. `unclassified_count` counts weight sets; `classification.verdicts.unknown.files` counts their files. A declared parent is another publication to inspect, never an automatic row replacement. An imatrix marker proves neither private inputs nor irrecoverability, and BF16 storage proves no original training provenance. Do not promise runtime quantization or other conversion features that are not implemented.
- `src/lib/lineage.ts` is a port of the CLI's `lineage.py`: family, generation, member, variants, formats, size — read from the name and labeled so. `src/lib/lineage-fixtures.json` is a copy of the CLI's `tests/fixtures/lineage-names.json`; both suites run the same table, so a grammar change lands in both repos with the same fixture. Family lens chips, `--sort family`'s order (`compareFamily`), and the **Lineage** view (`renderLineage` in `board.ts`: families → generations oldest first → members smallest first, a derivative nested under the parent its digest declares when that parent is on the board) all read from it. View and family live in the URL fragment (`#view=lineage&family=qwen`).
- Claims (`claim_json`, `POST/DELETE /api/boards/:id/entries/:eid/claim`) are board-side coordination like holders/status — never exported in catalog.json. Reporting `done` is the one client write to human columns (status→have; empty holders learns the client). A row with status `have` refuses un-marked claims (409 `{"error":"have"}`) — `refetch: true` (the CLI's `archive SOURCE --board`), `force`, or the holder's own continuing reports go through; that is what stops an out-of-date `--next` from re-downloading what the group holds. `entryToApi` filters claims past `CLAIM_TTL_MS` (`liveClaim`), so an abandoned claim stops rendering as in flight the moment it stops blocking new ones.
- Tests: `npm test`. Build: `PUBLIC_BOARDS_ENABLED=true npm run build`.
- Do not put a Node toolchain in `darsay/darsay` (the Python CLI repo).
- Provisioning is Wrangler + `ops/RUNBOOK.md`. Do not add Terraform, Ansible, or D1 auto-provision (omit `database_id`). RUNBOOK § *Credentials and permissions* is the disaster-recovery inventory of every secret, token, environment, and permission the site and the CLI's release pipeline need; when a workflow gains or loses one, change that table in the same commit.
- `public/robots.txt` may only Disallow `/b/`, `/api/`, `/boards`. Do not add GPTBot/ClaudeBot (or other AI crawler) Disallows; product docs should stay fetchable. Cloudflare dashboard AI-bot policy lives in `ops/RUNBOOK.md`.
- Board lenses (filters) live in `src/lib/lenses.ts` and the field guide (teaching cards) in `src/lib/primer.ts` + `src/lib/guide.ts`. Lenses are pure and decided from entry fields; hint lenses read the CLI's closed vocabulary (`gated`/`large`/`quant`/`redundant`/`subset`), the `archive` lens reads `size_basis`, `closed` reads the address, and name lenses (`abliterated`, `base`, `moe`, `spec`) read the repo name and say so in their blurb. Field-guide `doc` anchors must resolve against the docs currently synced under `src/content/docs` (the pinned CLI release), so a card that teaches something the pinned docs do not yet have a heading for links to the page, not an anchor, until the next docs sync. Lens/sort state lives in the URL fragment only (`#lens=…&sort=…`), never sent to the server. So does a deep link to a row, `#row=<id or source>`: `resolveRowLink`/`rowLinkTarget` in `board.ts` are pure and tested (a source in any spelling `canonicalizeSource` takes, Hub ids case-folded); the row's **Link** button copies `/b/<id>#row=owner/name` — the source, not the id, so it outlives a remove and re-add — and arriving scrolls to the row, spotlights it, and clears any lens or lineage view that hides it. Primer copy is authored text rendered through `inline()` (backticks/`**`/`*`); every `doc` anchor is checked against `src/content/docs` by `primer.test.ts`, so a docs re-sync that renames a heading fails the suite on purpose. Sizes in cards and row notes are GiB (the board's and the CLI's unit); recipe `#` comments keep the cookbook's wording. `src/lib/rownote.ts` is the card applied to the row it was opened from — pure text from entry fields, tested. Claims semantics (report at start / clean pause / registration, 24 h expiry) and `--next` order (partial, then desire, unrated last) come from `catalogs.mdx` and the CLI's `next_entry`; keep the desire and claims cards true to them.
- `src/worker/hints.ts` is a port of the CLI's `hints_for`/`derive_hints`/`_dominant_format` (same 20 GiB line, 1.75× redundancy factor, dtype widths). The worker writes `hints` into the digest on add and derives them when absent in `entryToApi`; the CLI's refresh overwrites both. Change the CLI first, then mirror here.
- Board recipe cards live in `src/lib/recipes.ts`: static, derived from entry fields plus the board page's own URL (no new catalog fields, no fetch per card). The `board` recipe teaches `archive SOURCE --board <board-url>` with the row's exact identity (source + revision + include) so the CLI's claim matches the row; the flag ships in CLI releases after 0.14.8. Command wording mirrors the CLI's `examples/README.md`; user text only ever appears inside `shellQuote`/`quoteGlob` single quotes, never in `#` comments, and is rendered with `textContent`.
- GGUF variant commands use the actual complete variant's exact selectors and original source/revision. No name heuristic or default quant chooses a variant. These are subset commands without `--board`, because they have a different identity from a whole-repository row. **Add variant** upserts only source/revision/include as a separate row, preserving existing curation; canonical identity matches show **On board**. Show variant precision and GGUF file sizes independently of parameter availability; producer-supplied `bytes_per_param` describes one complete selected model weight set, never the sum across alternatives.
